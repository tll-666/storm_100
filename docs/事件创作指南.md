# 暴雨100天 — 事件创作指南

## 一、JSON 结构

```json
{
  "version": 1,
  "events": [
    {
      "id": "唯一ID",
      "title": "事件标题",
      "type": "fixed | room | community | family | delayed",
      "day": "暴雨前第2天",
      "phase": "阶段ID",
      "location": "地点名称",
      "once": true,
      "conditions": {},
      "clues": ["线索1", "线索2"],
      "text": "正文（默认）",
      "text_variants": [],
      "choices": [],
      "merge": "合流目标ID"
    }
  ]
}
```

## 二、字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | √ | 全局唯一，建议前缀：`d2_`=第-2天, `d1_`=第-1天, `r1_`~`r100_`=暴雨第N天 |
| `title` | √ | 调试菜单显示用 |
| `type` | √ | `fixed`=主线固定触发, `room`=房间探索, `community`=社区相关, `family`=家庭互动, `delayed`=延迟回调 |
| `day` | √ | 所属天数标签 |
| `phase` | √ | 触发阶段，必须与 GameState.phase_id 匹配 |
| `location` | √ | 发生地点 |
| `once` | √ | `true`=只触发一次, `false`=可重复（如待命事件） |
| `conditions` | — | 触发条件字典 |
| `clues` | — | 事件相关的线索（调试用） |
| `text` | √ | 默认正文 |
| `text_variants` | — | 条件文本变体数组 |
| `choices` | √ | 选项数组（至少1个） |
| `merge` | √ | 合流目标 phase ID |

## 三、条件系统

```json
"conditions": {
  "phase": "目标阶段",
  "required_flags": ["必须已设置的flag"],
  "excluded_flags": ["必须未设置的flag"],
  "required_clues": ["必须已获取的clue"],
  "min_clues": 3,
  "required_items": ["必须拥有的物品ID"]
}
```

**优先级规则**：`excluded_flags` 优先于 `required_flags`——如果两个列表有相同的 flag，事件永不触发。

## 四、效果类型（effect）

| type | 参数 | 说明 |
|---|---|---|
| `set_flag` | `id` | 设置标记为 true |
| `clear_flag` | `id` | 清除标记 |
| `add_clue` | `id` | 添加线索 |
| `set_phase` | `value` | 切换阶段 |
| `set_time` | `label`, `segment` | 设置时间文本和时段 |
| `set_weather` | `value` | 设置天气文本 |
| `relationship` | `member`, `amount` | 调整信任值 |
| `member_stat` | `member`, `stat`, `amount` | 调整成员状态 |
| `add_water` | `amount` | 增加储备水（升） |
| `add_backup_power` | `amount` | 增加备用电力（格） |
| `set_preparation` | `value` | 设置准备方向 |
| `schedule_event` | `event_id`, `trigger_phase` | 安排延迟事件 |

## 五、成员ID与状态

**成员ID**：`player`, `partner`, `teen`, `child`, `elder`

**状态**：`health`, `hunger`, `thirst`, `morale`（均0-100，日常结算自动衰减）

**信任值**：通过 `relationship` effect 调整，无上下限，影响后续事件的文本变体和选项可用性。

## 六、物品ID（已实现）

`rice`, `flour`, `canned_food`, `vegetables`, `milk`, `chocolate`, `toilet_paper`, `detergent`, `bottled_water`, `batteries`, `power_bank`, `medicine`, `meat`, `eggs`

大件物品（米、面、整箱水、整提纸）占 2 格，其余 1 格。

## 七、时段（segment）

`morning`, `daytime`, `evening`, `night`

用于结算函数判断当前时段，夜间 `night` 会触发自动结算。

## 八、创作原则

### 8.1 空间发现优先
事件应该让玩家**在某个空间里发现坏消息**，而不是等时间到了自动弹框。
- 好："你走进厨房，拧开水龙头，流出来的是铁锈色的水。"
- 差："你发现供水出了问题。"（玩家怎么发现的？在哪？）

### 8.2 选择有意义
每个选项应该有至少两个有真实后果的选项：
- 一个选项的后果**立刻显现**（数值变化、阶段推进）
- 另一个的后果**延迟回响**（通过 `schedule_event` 跨天触发）

### 8.3 信息不可靠
`text_variants` 不仅用于"有电池→收音机更清晰"，更应该用于：
- 同一信息源在不同条件下给出**矛盾信息**
- 让玩家判断信哪个

### 8.4 文字质感
- 用**具体细节**（"沙发腿下按出水印"）替代抽象描述（"一楼潮湿"）
- 用**角色动作**（"老人把药推到桌子另一头"）替代数值描述（"elder morale -2"）
- 家庭对话要体现**性格差异**：老人说经历、伴侣说道理、大孩子说信息、小孩子说感受

### 8.5 合流设计
分支事件必须在 1-2 步内合流（`merge`），避免长期分叉导致的组合爆炸。

## 九、存档兼容

新增效果类型时，必须同步更新：
1. `event_manager.gd` 的 `_apply_effect` 方法
2. `event_manager.gd` 的 `_effects_summary` 方法
3. `game_state.gd` 的 `save_checkpoint` / `load_checkpoint` 方法

## 十、前三天事件参考

> 每个事件一行设问，选项缩写，结果一句话。机制标记用 emoji 简写：
> 🫗口渴 💧供水 ⚡供电 🍚食物 💊健康 😰精神 🏚房屋 🔫武器 🐺野兽 🌱种植 💰交易

### 第 -3 天：认识家

**E1. 检查配电箱**
触发：检查配电箱时
正文：线路老旧。连续潮湿可能跳闸。
→ 选项：记下来 / 回头再看
🫗 无即时后果。🏷 设 flag `breaker_checked`
⏳ 第 2 天停电后用此 flag 提供"早知道就买电池"的文字回响

**E2. 检查排水口**
触发：检查车库排水口时
正文：排水口积着落叶。车库比住宅低，水会从这里进来。
→ 选项：清理落叶 / 先不管
🏷 设 flag `drain_cleared` 或 `drain_ignored`
⏳ 第 3 天渗水事件用此 flag 改变文本和难度

**E3. 老人提醒储物**
触发：和老人对话后
正文："家里有点存货，心里不慌。买点罐头和电池。"
→ 选项：答应了 / 敷衍过去
😰 选答应的 → 老人精神 +2
⏳ 第 1 天购物时如果买了罐头/电池，老人精神再 +1

**E4. 小孩子要零食**
触发：和小孩子对话后
正文：小孩子抱着你腿："下雨天在家吃巧克力最好了。"
→ 选项：答应 / 看看再说 / 不行
😰 答应 → 小孩精神 +1。拒绝 → 小孩精神 -2
⏳ 第 1 天购物如果真买了巧克力，小孩精神 +3

### 第 -2 天：收集信息

**E5. 收音机预警**
触发：检查收音机（已有，建议保留）
正文：气象台说未来两天强降雨概率上调。学校和社区讨论临时安排。
→ 选项：记下提醒
💧⚡ 设 flag，push 到线索阶段
⏳ 这是第 1 天购物决策的依据

**E6. 排水管回声**
触发：检查车库排水口（已有，建议保留）
正文：排水管传来空洞回声。问题可能不在自家这一段。
→ 选项：记住声音
🏷 线索 `drain_echo`
⏳ 第 3 天渗水时变体文本引用此线索

**E7. 社区矛盾消息**
触发：检查大门
正文：学校说暂不停课。社区在统计低洼住户。两条消息像在描述不同的天气。
→ 选项：两条都记 / 只信学校的 / 只信社区的
🏷 记下→线索；只信一边→对应 flag
⏳ 信学校的→第 1 天要接孩子（已砍，可改为第 1 天购物时子女偏好）。信社区的→第 1 天购物时提示买水

**E8. 今天只做一件事**
触发：获得 ≥3 条线索后，在餐桌（已有，建议保留并精简）
正文："消息够多了。只能认真完成一件事。"
→ 选项：储水（💧+12L） / 充电（⚡+12格） / 检查路线（🏚 flag）
⏳ 选了储水→第 1 天开场变体；选了充电→第 2 天停电时有电池可选；选了路线→第 1 天购物文本框

### 第 -1 天：做决定

**E9. 清晨开场**（已有 `d1_morning_start`，建议保留）
正文："雨落下来了。学校停课，社区关门。五口人都在家。"
→ 选项：去超市 / 不出门
💰 去→购物阶段。不去→直接到晚上

**E10. 冰箱要坏了** 🆕
触发：第 -1 天，如果选了"不出门"，检查冰箱时
正文：冰箱还在转。但明天可能停电。生鲜要赶紧吃。
→ 选项：今晚全吃掉 / 留到明天
🍚 吃掉→饱腹+5，但生鲜消耗更快。留着→明天如果停电，生鲜坏掉损失 food×4
⏳ 第 2 天停电时，如果留了且没电→食物变质，健康-2

**E11. 小孩子数米缸** 🆕
触发：第 -1 天下午，路过食品柜
正文：小孩子蹲在米缸边数米粒："还剩多少天？"
→ 选项：说实话 / 骗他说还有很多
😰 说实话→小孩精神-1但你获得信任标记。骗他→精神稳定但你心里有数
⏳ 后续食物短缺时，信任标记影响小孩的反应（提前告知→接受；骗了→恐慌）

**E12. 伴侣检查窗户** 🆕
触发：第 -1 天傍晚
正文：伴侣把所有窗户推了一遍。"风越来越大了。"
→ 选项：一起检查 / 让她自己弄
😰 一起→伴侣精神+2。不管→伴侣精神-1
⏳ 第 2 天如果窗户受过检查且遇停电→风噪少，精神惩罚减半
