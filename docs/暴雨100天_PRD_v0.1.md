# 《暴雨100天》产品需求文档（PRD）

版本：v0.6（2026-07-22）

当前主工程：`versions/2d/project.godot`

引擎：Godot 4.7 Standard + GDScript + GL Compatibility

> 本版覆盖此前所有剧情与开发顺序。2D是当前唯一主版本；`versions/3d/`仅保留冻结实验。旧接人、重复购物、邻居、车库和广播真假剧情不再属于产品范围。

## 1. 产品概述

### 1.1 一句话介绍

玩家控制一个五口之家，在持续百日的极端暴雨中管理房屋、食物、饮水、卫生、精神和家庭选择，并最终走向军方救援、造船离开或坚持到暴雨结束之一。

### 1.2 核心体验

- 玩家能在一栋两层住宅内自由移动，靠近人物、家具和设施后主动查看。
- 时间自然流动，操作本身不按按钮额外扣分钟；熟练玩家可以完成更多事情。
- 世界不会等待玩家发现事件。漏掉检查不会被硬性阻止，但问题可能继续恶化。
- 每个选择优先造成小而可信的资源或状态变化，并在次日给出回应。
- 压迫感来自可观察的房屋变化、设备失效、资源竞争、人物活动和持续声音，而不只是一张地图变蓝。

### 1.3 当前开发目标

先完成“第0天 + 暴雨第1—7天”的室内纵向切片，验证：

1. 8分钟自然日是否合适。
2. 中午逐人配给是否清楚且有策略。
3. 食物变质、储水、净水和厕所是否互相产生资源竞争。
4. 地点发现事件与未发现后果是否公平。
5. 第1天选择能否在第2天闭环。

暴雨第8—15天暂时不写正式剧情，直到七日切片通过体验验证。

## 2. 产品边界

### 2.1 当前可玩空间

- 只保留房屋内部与封闭窗边观察区。
- 房屋共两层，包含客厅、厨房、储物区、卧室、卫生间、楼梯、玄关等必要功能区。
- 屋外以黑幕处理，不制作街道、前院、车库或可漫游阳台。
- 未来外出从玄关进入独立事件场景，不在主地图中模拟整条街。

### 2.2 当前不做

- 3D版本恢复开发。
- 开放世界、车辆驾驶和街道探索。
- 暴雨第8天后的正式剧情。
- 固定照明、洗衣机、污水转饮用水和完整疾病系统。
- 三个结局的完整流程和最终数值平衡。

## 3. 角色与控制权

家庭成员共五人：

| ID | 身份 | 当前差异 |
| --- | --- | --- |
| `player` | 父亲/主要操作角色 | 可外出；可饮酒和抽烟 |
| `partner` | 伴侣 | 成年人，可饮酒 |
| `teen` | 大孩子 | 如厕需求系数0.9 |
| `child` | 小孩子 | 如厕需求系数1.15 |
| `elder` | 老人 | 如厕需求系数1.25；可饮酒和抽烟 |

玩家以父亲在房屋内移动，但可以决定每一名角色当天吃什么、喝不喝水、未来由谁外出。NPC不是固定菜单图标：当前采用半自治活动，在需要如厕时走向卫生间并返回。

## 4. 核心循环

```text
观察HUD目标
→ 在房屋内移动
→ 靠近人物或设施并查看
→ 发现信息/整理资源/修理/储水/净水
→ 12:00为五人逐一分配食物和水
→ 继续处理下午问题
→ 20:00后在主卧结束当天
→ 查看真实已知信息的夜间结算
→ 承担次日后果
```

### 4.1 时间

- 暴雨日从07:00自然流动到23:00。
- 现实1秒对应游戏2分钟，完整可操作日约8分钟。
- 上午和下午共用一个连续计时器，不在中午重置倒计时。
- 行走、查看、修理和点击不额外消耗固定时间。
- 自身背包、说明书和剧情对话暂停时间。
- 冰箱、食品柜和水容器整理界面不暂停时间。
- 12:00后强制弹出当天配给；确认后下午继续使用同一计时器。
- 20:00后可睡觉，不要求完成或发现所有事件。

### 4.2 HUD与说明书

- HUD始终显示日期、时间、天气、水电状态、家庭资源与当前目标。
- 当前目标必须说明地点、对象和动作。
- 说明书列出可以前往的地点、每日主要循环和已检查环境状态。
- `T`只做快捷移动，不推进时间、不触发事件。
- 版本末尾必须明确显示“当前版本到此结束”。

## 5. 水、电与燃气

### 5.1 公共设施时间表

| 暴雨日 | 电网 | 自来水 |
| --- | --- | --- |
| 第1—3天 | 正常 | 可直接饮用 |
| 第4—5天 | 中断 | 仍出水，但不可直饮 |
| 第6天起 | 中断 | 完全停水 |

燃气为独立状态，当前切片中可用于烧开自来水原水。固定照明暂不制作，地图不会因停电变黑；停电通过冰箱、设备和资源压力体现。

### 5.2 电力设备

- 冰箱只有在外部电网和本地回路都正常时制冷。
- 第2天出现局部冰箱回路跳闸；第2—3天可用基础工具箱修复。
- 第4天外部电网中断后，修复配电箱不能恢复市电。
- 电池与充电宝只能为低功率设备预留，不能驱动电热水壶和电饭锅。

### 5.3 水质与容器

水分为直饮水、自来水原水、雨水和预处理雨水。真正污水不能转化为饮用水。

- 家中初始有一个可重复使用的15L水桶。
- 每个容器独立记录容量、数量、水质与存放位置；玩家可以逐个确认倒空，倒掉的水不会返还。
- 接水不限制点击次数，限制来自供水状态和空容器。
- 自来水原水可以用燃气烧开，单次最多3L，需要空目标容器。
- 雨水必须先预处理，再通过对应净水器和滤芯变为直饮水。

### 5.4 净水器

- 便携式手压净水器：小体积、低日处理量、便携滤芯。
- 多级重力净水器：大体积、高日处理量、多级滤芯组。
- 滤芯互不兼容；设备获得时自带一枚滤芯，后续滤芯由事件提供。
- 净水不限制点击次数，限制设备日处理量、滤芯、原水和目标容器。

## 6. 食物与配给

### 6.1 份数

食物按剩余份数管理。一袋大米可以提供12份，方便面2份，鱼罐头2份，蔬菜3份，牛奶2份，巧克力1份，生肉3份，鸡蛋1份，干饼干2份。

### 6.2 变质

- 冰箱制冷时易腐倒计时暂停。
- 无制冷后：生肉2天、鲜牛奶2天、蔬菜3天、鸡蛋6天。
- 查看时显示“新鲜”或剩余倒计时。
- 变质后不立即删除，而是逐渐减少份数。
- 冒险食用变质食物恢复部分饥饿，但扣健康与精神。

### 6.3 逐人分配

- 每名角色每天最多一次进食机会与一次1L饮水机会。
- 12:00后进入强制配给界面。
- 确认前可以反复调整每个人的食物和水。
- 普通食物的精神恢复最高到80；鲜牛奶与巧克力可以超过80。
- 部分食物同时恢复少量口渴。

### 6.4 酒与香烟

- 酒共4次，仅成年人可用；恢复饥饿、口渴和精神，损失健康。
- 香烟共5次，仅父亲和老人可用；恢复精神，损失健康。
- 二者精神恢复都可超过80。

## 7. 厕所与卫生

- 每人每日基础需求+15，进食+35，饮水+45，再乘角色系数。
- 四名NPC需求达到100后自动排队；父亲由玩家走到厕所主动使用。一次占用15游戏分钟。
- 马桶水箱容量12L；暴雨第6天起每次冲洗消耗2L。
- 水量不足产生未冲洗/脏污；累计3次变为堵塞。
- 脏污用4L非饮用水清理。
- 堵塞需要基础工具箱和6L非饮用水疏通。
- 无法使用是后续严重设施事件状态，不能靠普通清理修复。
- 脏污与长期憋迫会影响家庭精神和健康。

卫生间用半透明顶盖表达私密空间，仍让玩家知道人物在里面，避免人物突然消失。父亲使用期间短暂不能移动，但时间继续流动。

## 8. 事件系统

### 8.1 发现规则

- 晨间事件只说明公共状态。
- 地点和人物事件在玩家靠近并按E查看后才显示。
- 没发现的原事件不进入当天总结。
- 没发现不等于没发生：后果照常演化，并在成为可见现实时进入对应日期总结。
- 强制信息应通过HUD明确点名、NPC主动靠近或截止时间提醒，不能只依靠玩家碰巧走近。

### 8.2 数据要求

每个事件必须有唯一ID、阶段、条件、正文、选项、结果和合流点。选项影响优先采用小变化与延迟回响。新增效果类型时同步更新应用逻辑、调试摘要和存档。

### 8.3 第一日闭环

| 事件 | 地点 | 结果 |
| --- | --- | --- |
| 水龙头接水 | 厨房 | 容器按当天水质接满 |
| 冰箱生鲜 | 厨房 | 查看份数和新鲜度，中午逐人分配 |
| 窗沿渗水 | 一楼客厅窗户 | 2卷胶带封堵，或第2天客厅受潮、收音机失效、全家精神-2 |
| 睡觉 | 二楼主卧 | 20:00后结算并进入第2天 |

## 9. 第0天与前7天

| 日期 | 核心内容 | 闭环目的 |
| --- | --- | --- |
| 第0天 | 家庭交谈、房屋检查、一次购物、预报 | 教会基础操作，形成初始资源差异 |
| 暴雨1 | 正常水电、储水、冰箱、窗沿渗水 | 建立主动查看与可漏事件 |
| 暴雨2 | 窗户后果、冰箱局部跳闸 | 证明次日回应与修理价值 |
| 暴雨3 | 最后正常水电日 | 给玩家最后储备窗口 |
| 暴雨4 | 停电、自来水变原水 | 启动食物倒计时和水处理 |
| 暴雨5 | 最后管道水日 | 制造容器用途竞争 |
| 暴雨6 | 彻底停水、冲厕耗水 | 形成饮水与卫生竞争 |
| 暴雨7 | 完整室内循环 | 验证重复操作是否仍有取舍 |

第8—15天事件数据留空，不承接旧剧情。

## 10. 结局方向

三个结局预计在暴雨第80—100天间收束：

| 结局 | 长期条件方向 |
| --- | --- |
| 军方救援 | 提前获得可靠信息，并处理有限名额或冲突 |
| 造船离开 | 获得工具、指南、材料并完成船只 |
| 坚守百天 | 维持家庭和房屋直到暴雨结束 |

当前只在存档中预留相关状态，不在七日切片中发放关键剧情物品。

## 11. 视觉与声音方向

俯视2D无法只靠蓝色覆盖表达水位，因此未来的环境升级必须组合使用：

- 墙面水痕和明确高度基准线。
- 家具腿、门槛、台阶和墙脚的局部遮挡。
- 角色脚踝、膝盖、大腿、腰部的分级水体遮挡与移动反馈。
- 漂浮物、涟漪、雨线、漏水粒子、潮湿反光和水流方向。
- 房间声音变化：滴水、雨打窗、设备停转、脚步变成涉水声。
- HUD只解释玩家已经观察到的变化，不用大段文字代替画面。

是否让整栋房屋最终被淹、何时需要换地点，属于长线剧情问题，七日切片暂不决定。当前房屋设在相对高地，不把“百日暴雨”等同于每天线性上涨同样水深。

## 12. 技术与存档

- 主控制器：`versions/2d/scripts/main.gd`。
- 全局状态：`versions/2d/scripts/game_state.gd`。
- 事件系统：`versions/2d/scripts/event_manager.gd`。
- 程序化地图：`versions/2d/scripts/world_map.gd`。
- 事件数据：`versions/2d/data/events/*.json`。
- `F5`保存，`F9`读取；新增状态必须同步存取。
- `F1`仅在调试构建显示，每个需要长前置流程的新阶段都要加入跳转入口。
- `project.godot`的无意义编辑器改写不应提交。

## 13. 完成标准

- 新玩家能靠HUD和说明书找到厨房、配电箱、客厅窗户、卫生间和主卧。
- 玩家能理解一天只有一个连续计时器。
- 中午配给能为五人分别记录食物和水。
- 易腐食物显示正确倒计时，供电恢复/中断正确影响制冷。
- 三层水质、容器容量、烧开和两类滤芯不混淆。
- 厕所需求、排队、水箱、脏污和堵塞形成可理解反馈。
- 第1天不查看窗户时，第1天总结不剧透，第2天后果仍发生。
- 第7天结束时明确提示当前版本结束。
- 所有事件JSON可解析，引用ID存在，文本不再出现旧剧情人物与路线。

## 14. 风险

- 8分钟可能因UI操作慢而过度紧张，需要实玩后调整流速，不先拍脑袋平衡。
- 中午强制配给可能打断探索，应保证界面简洁并保留之前选择。
- 机制过多可能让第1天信息爆炸，必须通过地点发现分散教学。
- 俯视2D水位表现仍依赖美术与遮挡层级，需要单独做视觉原型。
- 第8天后过早堆剧情会掩盖第一周重复劳动问题。

## 15. 待确认问题

1. 初始220元、商品价格、背包6格、后备箱10格是否形成合理购买取舍。
2. 8分钟一天是否需要增加慢速或辅助暂停选项。
3. 两类净水器的单日处理量和滤芯寿命具体数值。
4. 每种食物恢复值、变质损失和酒烟代价是否平衡。
5. 第一个外出事件的地点、参与者、风险与次日小回响。
6. 第二周先增加室内压力，还是先投放一条长期结局线索。
7. 水位视觉原型采用哪些角色遮挡等级和墙面基准线。

## 16. 当前开发顺序

1. 完成第0天到暴雨第7天的机制实现和静态一致性检查。
2. 清除旧事件数据、旧剧情文档和运行时残留引用。
3. 在不增加剧情的前提下验证时间、配给、变质、水处理、厕所、事件发现和次日后果。
4. 根据实际游玩结果调整数值与UI，不先扩展第8—15天。
5. 和用户讨论并确认第一个外出事件，再写入JSON。
6. 为第8—15天逐日增加事件，每个选择先保证次日小回响。
7. 在第二周循环稳定后，选择一条结局路线做首个长期验证。
